## New candidates in type `0x1A`

Offsets below are zero-based in the complete packet, including `5AA5`. Type `0x1A` is a box message type, not a CAN arbitration ID.

- Bytes 13/14, big-endian: 857–2897 in profile 47 and 819–4955 in profile 46. In 47 it rises from about 860 to about 2800 and returns; in 46 there are accelerations and returns to about 820. A strong RPM candidate based on range and evolution, but it was not yet confirmed by documentation or a synchronized tachometer reading at this point.
- Bytes 10/11 as big-endian signed `int16`: fixed at 27 in profile 47; −226 to 220 in profile 46. A steering position/angle candidate because of bipolar variation and the reported turns; signal, scale, and unit were not yet confirmed at this point.
- 79 consistent complete `0x1A` packets in 47; 108 in 46. The type exists in both profiles; there is no evidence that changing the profile alone enabled RPM or steering. Test actions differ and have no synchronized markers.

Field 7/192 alternates between 0/2 in the first new test and 0/1/2 in the second, with pulses near 0.5 s. Do not identify it as angle or turn signal without validation: the OEM constant has an inconsistent name and old names have already proven misleading. Field 197 follows some illumination changes in the first trial (15/0); it is named panel brightness in the analyzed APK. Fields 107 and 197 do not vary in the second trial.

The second test's `0xF0` packet contains ASCII `H1W0PAF10A-220308`: a possible CAN-box version identifier, not definitive physical box identification.

## Version limitation and conclusion

Logs identify MS25.1202 (2125120210), whereas the previously supplied/decompiled MS APK is 26.0109 (2126010909). The ABI works, but newer APK internals must not automatically be attributed to the installed version.

The profile change is confirmed, the flow is active in both profiles, and corrected export worked. It is still not possible to claim that High is functionally superior, that speed was identified, or that each turn caused a specific field. The lack of an illumination transition in the second capture describes only the recorded window, not a demonstrated profile defect.

The next technical step was a `5AA5` stream parser with fragmentation/concatenation and checksum handling, followed by validation of `0x1A` candidates with the engine stationary at idle/known RPM and independently moved steering. No further test was required before making use of these data. No app, head-unit configuration, or service was changed in this analysis.
